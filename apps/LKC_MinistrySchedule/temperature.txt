對，這樣更乾淨。初始模板不要再細分太多，先分成兩種「表格性格」就好：

- **聚會型模板**：小組、團契、聚會類使用
- **事工型模板**：招待、敬拜、兒主、新家人、其他非小組團契服事使用

然後 optional 不需要預先列一堆，讓使用者在欄位設定裡自己「新增欄位名稱」就好。這樣管理成本最低。

你可以把架構改成這樣丟給 AI：

```js
const initialFieldTemplates = {
  "聚會型模板": {
    defaultFields: ["日期", "主題", "經文", "地點", "敬拜", "話語分享"],
    requiredFields: ["日期"]
  },

  "事工型模板": {
    defaultFields: ["日期", "地點"],
    requiredFields: ["日期"]
  }
};
```

**新增分頁時的流程**

```mermaid
flowchart TD
    A["管理者建立新分頁"] --> B["輸入 ID 與顯示名稱"]
    B --> C["選擇表格類型"]

    C --> C1["聚會型模板"]
    C --> C2["事工型模板"]

    C1 --> D1["套用聚會型預設欄位"]
    C2 --> D2["套用事工型預設欄位"]

    D1 --> E["建立第一版欄位設定"]
    D2 --> E

    E --> F["建立分頁"]
    F --> G["使用者進入排班頁"]

    G --> H["可立即使用三個大入口"]
    G --> I["也可進入表格欄位設定客製欄位"]
```

**欄位設定資料**

```js
const pageFieldConfig = {
  pageId: "VN01",
  fieldTemplateType: "聚會型模板",
  fields: ["日期", "主題", "經文", "地點", "敬拜", "話語分享"],
  requiredFields: ["日期"],
  customFields: [],
  updatedAt: "2026-05-26T00:00:00+08:00"
};
```

使用者後續如果新增欄位，例如「破冰」、「司會」、「點心」，就變成：

```js
const pageFieldConfig = {
  pageId: "VN01",
  fieldTemplateType: "聚會型模板",
  fields: ["日期", "地點", "破冰", "敬拜", "話語分享", "主題", "經文", "點心"],
  requiredFields: ["日期"],
  customFields: ["破冰", "點心"],
  updatedAt: "2026-05-26T00:00:00+08:00"
};
```

**欄位設定管理介面**

```mermaid
flowchart TD
    A["表格欄位設定"] --> B["顯示目前欄位"]
    B --> C["拖曳調整順序"]
    B --> D["停用非必要欄位"]
    B --> E["新增自訂欄位"]

    E --> F["輸入欄位名稱"]
    F --> G["加入目前欄位清單"]

    C --> H["儲存設定"]
    D --> H
    G --> H

    H --> I["更新該分頁 pageFieldConfig"]
    I --> J["表格、Excel、AI、布告欄全部套用新欄位"]
```

**整體原則**

```txt
1. 新增分頁時，只選「聚會型模板」或「事工型模板」。
2. 系統依模板建立第一版欄位。
3. optional 欄位不預先定義，使用者要什麼就自己新增。
4. requiredFields 不能刪除，至少保留日期。
5. 欄位順序以 pageFieldConfig.fields 為準。
6. 表格渲染、Excel 匯出、AI 解析、資料儲存、布告欄/總表，都使用同一份 fields。
```

這版的好處是：**新增時簡單，客製時自由，系統又不會被一堆模板名稱綁死。**
